# 面板视觉与交互规格（v0.2.1）

这份文档解释 `lib/client.js` 里「为什么是这些数字」。改样式前先看这里，避免把已经算过的账再算一遍。

## 1. 结构：三行 + 一块画布

```
┌ 44 导航行 ── 后退 前进 刷新 │ 地址栏 │ 打开 ─┐
├ 34 模式行 ── 标注开关        │  状态/插入反馈 ─┤
│                                               │
│           画面区（letterbox + 截图）           │  flex:1
│                 ┌ 浮卡 / 红条 ┐               │
└───────────────────────────────────────────────┘
```

- **为什么合并状态条**：旧版有独立的 26px 页脚，只放一个状态点 + 一句提示。在 360×780 的侧栏里，
  页脚 + 工具条 + 模式行会吃掉 110px（14%），而它们传达的是同一类信息（当前能不能点、点了会怎样）。
  现在「标注开关」和「状态」共用一行：一个管动作，一个管事实。
- **44 导航行** = 28 控件 + 上下各 8。28 是密集面板里「鼠标好点、视觉不臃肿」的下限；
  再矮（26）按钮的描边会挤在一起，再高（32）两行 chrome 就吃掉 100px。
- **34 模式行** = 24 胶囊 + 上下各 5。24 只给胶囊这类二次操作；它必须比主控件矮一档，
  否则会和工具条抢注意力。

### 两种宽度的差异（靠 `@container`，默认窄栏）

| | 360（默认） | ≥520（宽侧栏） | ≥640 |
|---|---|---|---|
| 左右内距 | 10 | 14 | 14 |
| 状态条 | 圆点 + `host/path` | 同上 | 追加 `· 页面标题` |
| 浮卡 | 整宽停靠（贴顶或贴底） | 整宽停靠 | ≥560 时锚定到落点附近 |
| 卡片里的 `256×44` | 隐藏 | 显示 | 显示 |
| 空态正文 | 11.5px / 292 宽 | 12px / 340 宽 | 同左 |

- **为什么锚定卡要 ≥560 才启用**：卡片本身 368 宽。侧栏 520 时，无论放在落点左边还是右边，
  都会盖住大半个画面，「贴着落点」的意义消失，不如老老实实做整宽停靠。
- **为什么标题要 ≥640 才出现**：640 以下 URL 已经占满状态条，标题会被压成 0 宽（看不见却还在占位），
  等于白吃空间。
- **窄栏内距为什么是 10 而不是 12/16**：360 宽下 16 会让可用宽度只剩 328，正文一行只能放 26 个汉字，
  标题和说明都要多折一行；10 + 画面自己留 6 的内边距，视觉上边框感仍然存在。

## 2. 尺寸刻度（4px 网格）

| 令牌 | 值 | 用在哪 | 理由 |
|---|---|---|---|
| 行高 | 44 / 34 | 工具条 / 模式行 | = 控件 + 2×8、胶囊 + 2×5 |
| 控件高 | 28 | 地址栏、按钮、图标按钮 | 点击热区够大；与 26 的分段控件同高 |
| 紧凑高 | 24 | 标注胶囊、卡片内按钮 | 比主控件矮一档，明确层级 |
| 内距 | 4 / 6 / 8 / 10 / 14 | 标签 / 控件内 / 控件间 / 面板边 / 宽栏边 | 只用 5 档，避免「差 2px」的随意感 |
| 圆角 | 4 / 6 / 8 / 10 / 999 | 标签 / 控件 / 浮层 / 浮卡 / 胶囊 | 层级越高越圆，封顶 10：再大就变卡片堆 |
| 字号 | 10 / 11 / 11.5 / 12 / 13 | 微标 / 元信息 / 控件 / 正文 / 标题 | 见下 |
| 图标 | 11 / 12 / 13 / 22 | 行内 / 次要 / 默认 / 空态 | 与相邻文字同高，不变形 |
| 阴影 | 2 处 | 浮卡 `0 16 36`、截图 `0 10 30` | 只有真正浮起来的才给阴影，其余用 1px 描边 |

**字号的理由**：CJK 在 11px 以下笔画会糊，所以 12px 是正文下限；10–11px 只给「非实质」信息
（计数、尺寸、快捷键、域名）。11.5px 是控件文字——比正文小半档但不糊，用于按钮/胶囊/地址栏。
13px 只给标题（空态标题、卡片里的元素名）。

## 3. 颜色：按语义分工，不按色板铺

| 层 | 值 | 语义 |
|---|---|---|
| letterbox | `#010409` | 截图之外的「屏幕底色」，比画布更深，让截图浮起来 |
| 画布 | `#0d1117` | 地址栏、备注输入（凹）|
| 面板 | `#161b22` | 工具条、模式行（平）|
| 控件 | `#21262d` | 分段控件、胶囊底（凸一档）|
| 悬停 | `#30363d` | hover / active |
| 描边 | `#30363d` / `#21262d` | 结构线 / 分隔线 |
| 主色 | `#58a6ff` | 只给两处：当前标注模式、选中的元素标签 |
| 绿 | `#238636` | 每屏只有一个主按钮 |
| 警示 | `#d29922` / `#f85149` | 画面中断 / 连接失败 |

三条硬规则：

1. **每屏只有一个绿色主按钮**。连接失败时工具栏的「启动」会降级成 ghost，把唯一的主按钮让给画面中央的「重试」。
2. **蓝色不用于装饰**。它只表示「现在处于标注态」和「这个元素被选中了」。
3. **状态点四色**：绿=浏览器在线、琥珀=画面中断（还有旧帧）、红=连不上、灰=还在连。

`color-scheme: dark` 写在根节点上，否则原生光标、选择色、滚动条会是浅色的，在深色面板里非常明显。

## 4. 五种状态

| 状态 | 触发 | 版式 | 文案 / 动作 |
|---|---|---|---|
| 连接中 | 首次 `/status` 未回 | 虚线方框内 18px 转圈 + 标题 + 一行说明 | 「正在连接浏览器…」／无需动作（工具条按钮禁用）|
| 未连接 | `ok:false` 或请求超时 | 红色警示图 + mono 错误框（可滚动，最大 76px）+ 主按钮 | 「连接失败」／「重试」+ 设置提示 |
| 空页面 | 连上了但 `about:blank` | 指针图 + 标题 + 一行说明 | 「输入网址开始」／直接去地址栏（不给按钮，避免两个绿）|
| 已连接 | 有页面 | 画面 + 状态点 + 地址；错误走底部红条 | 红条：图标 + 两行截断 + 「重试」|
| 已选中 | 点中元素 | 画面 + 落点圆钉 + 浮卡 | 卡片：标签/文本/尺寸 + 输入 + 「将插入」预览 + Enter/Esc |

- 连接中/未连接/空页面三态共用同一套骨架（`art + 标题 + 说明`），只换图形与文案，保证切换时不跳版。
- 有画面时的错误**不挤走画面**，只在底部叠一条红条（`-webkit-line-clamp:2`，完整内容进 `title`）。
- 「已连接但第一帧没到」单独有一档：「正在获取画面…」，避免空态文案闪一下再消失。

## 5. 交互细节

**标注模式的可视反馈（四层叠加，任一层失效都还能看出来）**
1. 胶囊：`aria-pressed` + 蓝底蓝边 + 文案变「标注中」；
2. 画面区：1px 蓝色 inset 环；
3. 画面本身：`cursor:crosshair`；
4. 左上角提示胶囊：「点画面选元素」+ `Esc` 键帽。

**点选**
- 按下立即在落点画**虚线圆钉**（`ab-pin-wait` 呼吸），请求回来换成实心圆钉。没有这一步，
  300ms 的等待会让人以为没点上。
- 落点用 `frame.getBoundingClientRect()` 换算回截图坐标：`x = fx × naturalWidth`。
  **这是本次修掉的旧 bug**：旧实现用 `naturalWidth / imgRect.width` 换算，而 `object-fit:contain`
  时图片实际渲染尺寸小于元素宽度，letterbox 方向和大小都会让坐标偏移。

**浮卡**
- 落点在上半区→卡片贴底；在下半区→贴顶。保证**卡片永远不盖住刚点的那个元素**。
- ≥560 宽时改为锚定：卡片出现在落点右下 16px；放不下就翻转/夹取到画面内。
- 出现即 `autoFocus` 输入框，光标可直接打字；`Enter` 插入、`Esc` 取消（输入框内单独处理并 `stopPropagation`）。
- 卡片里有「将插入」一行实时预览最终落进对话的整行文本，含截断 + `title` 全文。
- 已经在选中的状态下再点别的元素：换元素、**保留已输入的备注**（用户常见动作是「点歪了重来」）。

**插入后的反馈**
- 卡片收起、落点清除、计数 +1（`N 条` 在这个会话里一直保留）；
- 模式行右侧的状态位临时换成绿色「✓ 已插入 button#submit」，1.8 秒后淡回地址；
- 焦点回到标注开关（键盘用户可继续 Tab）；
- **标注模式保持开启**：下一步通常是接着点第二个元素，不该让用户再开一次。

**轮询**
- `/status` 3s 一次（地址/连接态），`/shot` 用后端返回的 `config.pollMs`（默认 1.2s）。
- 画面后台预取成 blob，解码完成后才换 `src`——避免旧实现每 1.2s 把 `<img>` 指到新 URL 时的闪白与错帧。
- `props.visible === false`（宿主把 tab 停靠起来）或 `document.hidden` 时**完全停止轮询**；
  重新可见立刻补一帧。旧实现不看 `visible`，隐藏 tab 也会每 1.2s 打一次 `/status`
  （而这个接口会顺手 `ensure()` 拉起 Chrome）。

## 6. 明确不做（以及为什么）

| 不做 | 原因 |
|---|---|
| 元素矩形高亮 | `element.rect` 是视口 CSS px，截图像素是 `CSS × dpr`，后端没给 viewport 宽度，画框一定错位。落点圆钉是唯一能 100% 对上的标记。 |
| 画面缩放/平移 | 需要后端暴露 viewport / 滚动接口，超出「不改接口」的边界。 |
| 跟随宿主明暗主题 | 面板本体是「浏览器窗」，长期和截图并置；浅色 chrome 会抢走截图的注意力，而且半套浅色（画布仍是深色）比全深色更难看。代价：浅色宿主里它是深色窗，需要用户知情。 |
| 多元素批量标注 | 会让「一行文本进对话」的契约变成列表，agent 侧解析要一起改。 |
